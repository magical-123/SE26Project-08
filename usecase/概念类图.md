# InfoDigest（知食）— 概念类图

> **项目名称**：InfoDigest（知食）— 全域碎片化信息捕获与数字饮食管理平台  
> **文档用途**：供绘制概念类图（Conceptual Class Diagram）参考  
> **版本**：v1.0

---

## 1. 概述

本文档定义了 InfoDigest 系统的核心领域概念类，按**6 大功能模块**组织，涵盖类名、关键属性、职责以及类之间的关联关系。每个类只列出概念层面最重要的属性，用于绘制概念类图时参考。

---

## 2. 核心概念类

### 2.1 用户与社交模块

#### User（用户）

| 项目 | 内容 |
|------|------|
| **职责** | 平台的核心参与者，拥有信息源、笔记、报告、知识图谱等所有数据 |
| **关键属性** | `用户ID` / `用户名` / `邮箱` / `密码哈希` / `注册时间` / `默认可见性` |
| **关联关系** | — 拥有 **1..*** InformationItem（信息源） |
| | — 拥有 **1..*** Note（笔记） |
| | — 拥有 **1..*** ReviewCard（复习卡片） |
| | — 拥有 **1..*** UserReport（报告） |
| | — 发起/接收 **0..*** Friendship（好友关系） |
| | — 授权 **0..*** PlatformAuth（平台授权） |
| | — 拥有 **1** 个 KnowledgeGraph（知识图谱） |

#### Friendship（好友关系）

| 项目 | 内容 |
|------|------|
| **职责** | 记录用户之间的好友关系及状态 |
| **关键属性** | `关系ID` / `请求方用户ID` / `接收方用户ID` / `状态(待接受/已接受)` / `创建时间` |
| **关联关系** | — 关联 **2** 个 User（请求方和接收方） |

#### Poster（分享海报）

| 项目 | 内容 |
|------|------|
| **职责** | 用户将每日营养报告生成的分享海报 |
| **关键属性** | `海报ID` / `所属用户ID` / `生成时间` / `海报图片数据` / `关联报告ID` |
| **关联关系** | — 属于 **1** 个 User |
| | — 关联 **1** 个 UserReport |

---

### 2.2 信息源管理模块

#### PlatformAuth（平台授权）

| 项目 | 内容 |
|------|------|
| **职责** | 记录用户在第三方平台（B站、知乎、播客等）的授权信息 |
| **关键属性** | `授权ID` / `所属用户ID` / `平台名称` / `授权方式(Cookie/MCP)` / `授权状态` / `过期时间` / `加密凭证` |
| **关联关系** | — 属于 **1** 个 User |
| | — 产生 **0..*** InformationItem |

#### InformationItem（信息源/信息条目）

| 项目 | 内容 |
|------|------|
| **职责** | 从第三方平台捕获的单条浏览记录，是系统的核心数据单元 |
| **关键属性** | `信息ID` / `所属用户ID` / `标题` / `URL链接` / `来源平台` / `作者` / `分类标签` / `浏览时长(分钟)` / `原始内容` / `处理状态(未处理/已处理)` / `是否优质` / `抓取时间` |
| **关联关系** | — 属于 **1** 个 User |
| | — 属于 **1** 个 PlatformAuth |
| | — 拥有 **0..1** 个 Note（笔记） |
| | — 被关联到 **0..*** KnowledgeNode（知识图谱节点） |
| | — 被引用到 **0..*** ReviewCard（复习卡片） |

---

### 2.3 笔记与标注模块

#### Note（笔记）

| 项目 | 内容 |
|------|------|
| **职责** | 用户对某个信息源撰写的个人笔记，标注后将该信息源升格为"优质" |
| **关键属性** | `笔记ID` / `所属用户ID` / `关联信息ID` / `笔记内容` / `情感标签` / `创建时间` / `更新时间` |
| **关联关系** | — 属于 **1** 个 User |
| | — 关联 **1** 个 InformationItem |

---

### 2.4 报告与分析模块

#### UserReport（用户报告）

| 项目 | 内容 |
|------|------|
| **职责** | 自动生成的每日/每周知识摄入总结报告 |
| **关键属性** | `报告ID` / `所属用户ID` / `报告类型(日报/周报)` / `报告日期` / `营养数据(JSON)` / `洞察标题` / `洞察摘要` / `洞察全文` / `词云数据(JSON)` / `生成时间` |
| **关联关系** | — 属于 **1** 个 User |
| | — 包含 **1** 个 NutritionLabel（营养成分表） |
| | — 包含 **1** 个 TrendAnalysis（关注点流变分析） |
| | — 可生成 **0..1** 个 Poster（海报） |

#### NutritionLabel（信息营养成分表）

| 项目 | 内容 |
|------|------|
| **职责** | AI 对用户信息摄入进行的语义分类与营养度打分结果 |
| **关键属性** | `营养ID` / `关联报告ID` / `分类数据(JSON)` — 例如 `[{类别: "深度知识", 占比: 30%, 时长: 45分钟}, {类别: "娱乐短剧", 占比: 70%, 时长: 105分钟}]` |
| **关联关系** | — 属于 **1** 个 UserReport |

#### TrendAnalysis（关注点流变分析）

| 项目 | 内容 |
|------|------|
| **职责** | 用户近期信息摄入话题的聚类分析与关注趋势变化 |
| **关键属性** | `分析ID` / `关联报告ID` / `话题聚类数据(JSON)` / `趋势变化数据(JSON)` / `核心收获摘要` |
| **关联关系** | — 属于 **1** 个 UserReport |

---

### 2.5 知识图谱模块

#### KnowledgeGraph（知识图谱）

| 项目 | 内容 |
|------|------|
| **职责** | 用户个人知识图谱的根容器，包含所有节点和边 |
| **关键属性** | `图谱ID` / `所属用户ID` / `最后更新时间` |
| **关联关系** | — 属于 **1** 个 User |
| | — 包含 **1..*** KnowledgeNode（知识节点） |
| | — 包含 **0..*** KnowledgeEdge（知识关联） |

#### KnowledgeNode（知识节点）

| 项目 | 内容 |
|------|------|
| **职责** | 知识图谱中的单个概念实体，由 AI 从优质信息源中抽取 |
| **关键属性** | `节点ID` / `所属图谱ID` / `名称` / `类型` / `描述` / `权重` / `可见性(公开/好友/私密)` |
| **关联关系** | — 属于 **1** 个 KnowledgeGraph |
| | — 关联 **0..*** InformationItem（来源信息源） |
| | — 通过 KnowledgeEdge 关联 **0..*** 其他 KnowledgeNode |

#### KnowledgeEdge（知识关联）

| 项目 | 内容 |
|------|------|
| **职责** | 两个知识节点之间的语义关联关系 |
| **关键属性** | `关联ID` / `所属图谱ID` / `源节点ID` / `目标节点ID` / `关系类型(如"关联于"、"包含"、"引申")` / `权重` |
| **关联关系** | — 属于 **1** 个 KnowledgeGraph |
| | — 关联 **2** 个 KnowledgeNode（源节点和目标节点） |

---

### 2.6 进阶功能模块

#### ReviewCard（复习卡片）

| 项目 | 内容 |
|------|------|
| **职责** | 基于艾宾浩斯遗忘曲线生成的抗遗忘复习卡片 |
| **关键属性** | `卡片ID` / `所属用户ID` / `标题` / `内容(金句/核心概念)` / `来源平台` / `来源信息ID` / `计划复习日期` / `复习次数` / `创建时间` |
| **关联关系** | — 属于 **1** 个 User |
| | — 引用 **0..1** 个 InformationItem |

#### Recommendation（跨平台推荐）

| 项目 | 内容 |
|------|------|
| **职责** | 基于用户知识图谱，AI 在全网嗅探后推送的高价值信息推荐 |
| **关键属性** | `推荐ID` / `所属用户ID` / `标题` / `URL` / `来源平台` / `推荐理由` / `关联知识节点` / `推送时间` / `是否已读` |
| **关联关系** | — 属于 **1** 个 User |
| | — 关联 **0..*** KnowledgeNode |

## 3. 类间关系总览

### 3.1 关联关系汇总

| 类 A | 多重性 | 关系 | 多重性 | 类 B | 说明 |
|------|:------:|------|:------:|------|------|
| **User** | 1 | 拥有 → | 1..* | InformationItem | 用户拥有多条信息源 |
| **User** | 1 | 拥有 → | 0..* | Note | 用户可写多条笔记 |
| **User** | 1 | 拥有 → | 0..* | ReviewCard | 用户可有多张复习卡片 |
| **User** | 1 | 拥有 → | 0..* | UserReport | 用户可有多份报告 |
| **User** | 1 | 拥有 → | 1 | KnowledgeGraph | 用户拥有一个知识图谱 |
| **User** | 1 | 授权 → | 0..* | PlatformAuth | 用户可授权多个平台 |
| **User** | 1 | 发起 → | 0..* | Friendship | 用户可发起多个好友请求 |
| **User** | 1 | 接收 ← | 0..* | Friendship | 用户可接收多个好友请求 |
| **User** | 1 | 生成 → | 0..* | Poster | 用户可生成多张海报 |
| **User** | 1 | 接收 → | 0..* | Recommendation | 用户可接收多条推荐 |
| **PlatformAuth** | 1 | 产生 → | 0..* | InformationItem | 一个平台授权产生多条信息源 |
| **InformationItem** | 1 | 拥有 → | 0..1 | Note | 一条信息源最多有一条笔记 |
| **InformationItem** | 1 | 被引用 → | 0..* | ReviewCard | 信息源可被多张复习卡片引用 |
| **InformationItem** | 0..* | 关联 → | 0..* | KnowledgeNode | 信息源关联到知识图谱节点 |
| **UserReport** | 1 | 包含 → | 1 | NutritionLabel | 报告包含一个营养成分表 |
| **UserReport** | 1 | 包含 → | 1 | TrendAnalysis | 报告包含一个流变分析 |
| **UserReport** | 1 | 生成 → | 0..1 | Poster | 报告可生成一张海报 |
| **KnowledgeGraph** | 1 | 包含 → | 1..* | KnowledgeNode | 图谱包含多个知识节点 |
| **KnowledgeGraph** | 1 | 包含 → | 0..* | KnowledgeEdge | 图谱包含多条知识关联 |
| **KnowledgeNode** | 1 | 关联 → | 0..* | InformationItem | 节点关联到信息源 |
| **KnowledgeNode** | 1 | 出边 → | 0..* | KnowledgeEdge | 节点作为关联的源 |
| **KnowledgeNode** | 1 | 入边 ← | 0..* | KnowledgeEdge | 节点作为关联的目标 |
| **Recommendation** | 1 | 关联 → | 0..* | KnowledgeNode | 推荐基于知识图谱节点 |

### 3.2 继承/泛化关系

| 父类 | 子类 | 说明 |
|------|------|------|
| 无 | 无 | 当前领域模型暂未涉及继承关系，保持扁平化设计 |

### 3.3 聚合/组合关系

| 整体类 | 部分类 | 关系类型 | 说明 |
|--------|--------|:--------:|------|
| **UserReport** | NutritionLabel | **组合** | 营养成分表随报告创建/删除，不可独立存在 |
| **UserReport** | TrendAnalysis | **组合** | 流变分析随报告创建/删除，不可独立存在 |
| **KnowledgeGraph** | KnowledgeNode | **组合** | 节点随图谱创建/删除，不可独立存在 |
| **KnowledgeGraph** | KnowledgeEdge | **组合** | 关联随图谱创建/删除，不可独立存在 |

## 5. 绘制建议

### 5.1 推荐布局方式

按功能模块将类图分为 6 个区域，从左上到右下排列：

```
┌──────────────────────────────────────────────────────────────────┐
│  ┌─────────┐  ┌──────────────────┐  ┌──────────────────────┐    │
│  │ 用户与社交 │  │   信息源管理      │  │    笔记与标注         │    │
│  │ (User,   │  │ (PlatformAuth,   │  │ (Note)              │    │
│  │Friendship)│  │  InformationItem)│  │                      │    │
│  └─────────┘  └──────────────────┘  └──────────────────────┘    │
│                                                                  │
│  ┌──────────────────┐  ┌──────────────────┐  ┌──────────────┐    │
│  │   报告与分析      │  │    知识图谱       │  │   进阶功能    │    │
│  │ (UserReport,     │  │ (KnowledgeGraph, │  │ (ReviewCard, │    │
│  │  NutritionLabel, │  │  KnowledgeNode,  │  │  Poster,     │    │
│  │  TrendAnalysis)  │  │  KnowledgeEdge,  │  │  Recommend)  │    │
│  │                   │  │  Recommendation) │  │              │    │
│  └──────────────────┘  └──────────────────┘  └──────────────┘    │

└──────────────────────────────────────────────────────────────────┘
```

### 5.2 绘制要点

1. **类框格式**：三个分区 — 类名 / 属性列表 / 职责（可选）
2. **关联线**：直线连接，标注多重性（1, 0..\*, 1..\*）和角色名
3. **组合关系**：用实心菱形箭头，如 `UserReport ◆──→ NutritionLabel`
4. **注意**：InformationItem 与 KnowledgeNode 之间的多对多关联，可能需要使用关联类
5. **User 类**作为核心，建议放在图中央，向各模块辐射连接

- **Draw.io / diagrams.net**：免费，支持所有 UML 类图符号
- **PlantUML**：代码驱动，可快速迭代
- **Visual Paradigm**：功能全面的 UML 建模工具
