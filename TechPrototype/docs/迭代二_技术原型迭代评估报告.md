## 二、质量情况

本次迭代的代码通过GitHub Flow流程管理，所有变更均以feature branch → PR → review → merge的方式进入main分支，所有PR均已成功合并。后端分层清晰，Controller/Service/Repository职责分明，AIService实现了OpenAI/Claude/Gemini/DeepSeek等8+模型供应商的统一抽象，扩展性强。爬虫模块容错机制完善，支持Token自动刷新、指数退避重试和平台降级策略。前端8个页面覆盖了Vision文档的核心功能，ECharts图表和ReactFlow知识图谱的视觉效果较好，海报导出功能可用。

存在的问题主要集中在两个方面。一是知乎和小红书爬虫受平台反爬限制严重：知乎Playwright环境的浏览器指纹被检测，三个stealth包（playwright-stealth、playwright-extra-plugin-stealth）经测试均为假包或无效；小红书无公开用户数据API，Playwright亦触发风控error 300012。二是0测试覆盖——75+ API端点的项目没有任何单元测试或集成测试，回归风险较高。

***

## 三、问题、变更和返工

### 遇到的问题

- 知乎推荐流API返回401/404，经诊断确认为x-zse-96签名和浏览器指纹多层反爬，三个stealth相关npm包均为假包，最终降级为无登录/explore公共发现页。
- 小红书Playwright触犯风控error 300012，平台无公开用户数据API，仅能抓取/explore公开推荐流。

### 变更记录

- Vision文档5.2节的4种情感标签移除，简化信息源标注为用户自由文本笔记+优质标记。
- Apple Podcasts平台替换为GitHub和小红书，按课程组要求调整。

### 返工情况

- 知乎/小红书反爬对抗返工：2轮。第1轮从API直调改为DOM抓取，第2轮尝试stealth插件后放弃。

总体返工较少，主要集中在平台侧不可控的反爬对抗上。

## 四、经验和教训

### 做得好的方面

- 架构分层规范，后端三层分离、前端组件化拆分、爬虫平台解耦，代码可维护性好。
- AI服务层抽象到位，8+模型供应商统一接口，切换配置即可换模型。
- 爬虫容错链路完整，Token自动刷新、指数退避重试、平台逐级降级，整个抓取流程不会因单平台失败而崩溃。
- GitHub Flow严格执行，所有代码通过feature branch → PR → review流程合入，main分支始终可部署。

### 需要改进的方面

- 反爬可行性评估应在技术选型阶段完成，知乎和小红书的Playwright方案在迭代二中反复尝试后证明不可行。后续有反爬需求时，应先做独立PoC验证。
- 项目达到75+ API端点的规模，却无任何自动化测试，回归风险较高，建议迭代三补充核心Controller的集成测试。

总体来看，本次迭代二完成了技术原型的核心目标，前后端和爬虫三大模块均已打通全链路，AI分析、营养评分、知识图谱、报告生成等P0功能可用。主要短板在反爬对抗的局限性和自动化测试的缺失，建议迭代三优先解决。
