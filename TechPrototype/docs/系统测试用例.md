# InfoDigest（知食）系统测试用例

## 1. 功能测试用例 - 信息捕获与AI分析

**测试目标**：验证系统能够正确捕获信息并自动触发AI分析生成营养成分和摘要。

**测试步骤**：
1. 登录系统，在捕获箱点击"添加"按钮
2. 输入标题和内容（如技术文章），点击"保存"
3. 等待AI分析完成，点击信息项查看详情抽屉
4. 验证营养成分五维度显示、AI摘要和关键词标签

**预期结果**：
- 信息成功保存到捕获箱
- 系统自动触发AI分析，后台异步处理
- 分析完成后，信息项显示"已分析"状态
- 营养成分五个维度总和为100%，且符合内容特征（技术知识类内容应有较高的蛋白质占比）
- AI摘要简洁准确，长度在50-200字之间
- 关键词标签至少提取3-5个，且与内容相关

**使用工具**：
- 手动测试 + Chrome DevTools（监控网络请求和响应）
- Postman（可选，用于API级别的测试验证）

## 2. 可靠性测试用例 - 数据库连接异常恢复

**测试目标**：验证系统在数据库连接中断后能够自动重连并恢复正常服务。

**测试步骤**：
1. 启动系统并登录，在捕获箱添加一条信息
2. 使用MySQL Workbench强制关闭数据库连接
3. 尝试刷新捕获箱或添加新信息，观察错误提示和日志
4. 恢复数据库连接，等待30秒后重新操作，检查数据一致性

**预期结果**：
- 数据库断开时，系统返回友好的错误提示（如"服务暂时不可用，请稍后重试"）
- 系统不会崩溃或出现白屏
- 后端日志记录数据库连接异常信息
- 数据库恢复后，系统自动重新建立连接池
- 所有功能恢复正常，无需重启后端服务
- 断开期间未成功保存的数据不会丢失（前端有重试机制或提示用户重新提交）
- 断开前已保存的数据完整保留

**使用工具**：
- MySQL Workbench 或 DBeaver（数据库管理工具，用于模拟数据库故障）
- Spring Boot Actuator（监控应用健康状态和数据库连接池）
- 系统日志查看工具（查看异常堆栈和恢复过程）

## 3. 性能测试用例 - 词云生成并发处理能力

**测试目标**：验证系统在多用户并发请求生成词云时的处理能力和响应时间。

**测试步骤**：
1. 为10个测试账号准备50-100条已分析信息
2. 配置JMeter：50并发用户，请求POST /api/report/wordcloud/regenerate
3. 设置Ramp-Up 10秒，运行5分钟
4. 记录平均响应时间、P95、吞吐量、错误率
5. 监控服务器CPU、内存和数据库连接数

**预期结果**：
- 系统能够成功处理所有50个并发词云生成请求
- 平均响应时间不超过3秒
- 95%响应时间（P95）不超过5秒
- 系统吞吐量达到至少10 TPS
- 错误率为0%（所有请求成功）
- 服务器CPU使用率不超过80%
- 数据库连接池未耗尽（连接数在配置范围内）
- 生成的词云数据准确且完整

**使用工具**：
- Apache JMeter 5.6+（性能测试工具，模拟并发用户请求）
- Grafana + Prometheus（监控系统资源使用情况）
- MySQL Performance Schema（监控数据库性能指标）

## 4. 易用性测试用例 - 新用户首次使用流程

**测试目标**：验证新用户能够在5分钟内完成注册并成功添加第一条信息。

**测试步骤**：
1. 招募5名未使用过系统的测试用户（不同年龄和技术背景）
2. 提供系统地址，不提供使用说明，录屏观察操作过程
3. 要求完成：注册、登录、添加信息、查看AI分析结果
4. 记录每步耗时和困难点
5. 测试后填写SUS问卷，统计完成率、平均耗时和SUS评分

**预期结果**：
- 至少80%的用户能够在无指导情况下完成全部任务
- 平均完成时间不超过5分钟
- 所有用户能够在3分钟内完成注册和登录
- 没有用户在添加信息环节卡住超过2分钟
- SUS评分达到70分以上（良好的易用性水平）
- 用户反馈主要操作流程清晰、界面直观
- 如有用户遇到困难，能通过界面提示信息自行解决

**使用工具**：
- OBS Studio（录屏工具，记录用户操作过程）
- Google Forms 或问卷星（SUS问卷收集工具）
- Hotjar 或 Microsoft Clarity（可选，用户行为分析工具，追踪点击热力图和用户路径）

## 5. 兼容性测试用例 - 跨浏览器前端功能验证

**测试目标**：验证系统在主流浏览器和不同操作系统上的功能一致性和显示正确性。

**测试步骤**：
1. 准备测试环境：Windows 11 (Chrome/Edge)、macOS (Safari/Firefox)、移动端 (iOS Safari/Android Chrome)
2. 在每个浏览器中测试：首页、注册登录、捕获箱、仪表盘、报告、知识图谱、设置等页面
3. 验证页面布局、CSS样式、JavaScript功能、ECharts图表渲染和响应式设计
4. 记录每个浏览器中的问题（截图+描述）

**预期结果**：
- 所有核心功能在6种浏览器环境中均能正常运行
- 页面布局在桌面浏览器（Chrome、Edge、Safari、Firefox）上完全一致
- 移动端浏览器能够正确显示响应式布局，触摸交互流畅
- ECharts图表在所有浏览器中正确渲染（词云、饼图、折线图）
- CSS动画和过渡效果在所有浏览器中表现一致
- 不出现仅在特定浏览器中存在的JavaScript错误
- 允许的差异：Safari和Firefox的滚动条样式可能略有不同（非功能性差异）
- 移动端的交互方式（如长按、滑动）按照移动设备习惯调整

**使用工具**：
- BrowserStack 或 LambdaTest（云端跨浏览器测试平台，支持真实设备测试）
- Chrome DevTools、Firefox Developer Tools、Safari Web Inspector（浏览器开发者工具，用于调试）
- Responsively App（开源工具，同时预览多个设备尺寸）
- Can I Use（查询CSS和JavaScript特性的浏览器兼容性）

## 总结

以上5个测试用例覆盖了InfoDigest系统的主要测试维度：

1. **功能测试**：验证核心业务流程（信息捕获与AI分析）
2. **可靠性测试**：验证系统容错能力（数据库异常恢复）
3. **性能测试**：验证系统负载能力（并发词云生成）
4. **易用性测试**：验证用户体验（新用户上手流程）
5. **兼容性测试**：验证跨平台一致性（多浏览器环境）

这些测试用例可以作为系统质量保障的基础，在实际测试过程中可根据具体需求进行调整和扩展。
