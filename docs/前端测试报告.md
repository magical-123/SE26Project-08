# InfoDigest 前端测试报告

## 1. 测试概况

| 项目 | 内容 |
|---|---|
| 测试日期 | 2026-07-30 |
| 测试对象 | InfoDigest 前端应用 |
| 测试框架 | Vitest + React Testing Library |
| 测试文件 | 33 个 |
| 测试用例 | 864 个 |
| 测试结果 | 864 个全部通过 |
| 覆盖率报告 | `frontend/coverage/` |

本次测试覆盖前端 API 封装、数据 Hook、布局、页面组件、信息卡片、报告、设置、知识图谱及社交相关组件，重点验证正常流程、错误状态、加载状态、用户交互和数据转换逻辑。

## 2. 覆盖率结果

| 指标 | 覆盖率 | 结论 |
|---|---:|---|
| Statements | 90.02% | 达到语句覆盖率超过 90% 的要求 |
| Lines | 91.12% | 达到 90% 以上 |
| Functions | 92.70% | 达到 90% 以上 |
| Branches | 77.81% | 尚未达到 90%，仍有条件分支需要补测 |

按照“语句覆盖率超过 90%”的项目要求，本次前端测试已达标。函数覆盖率和行覆盖率也超过 90%；分支覆盖率相对较低，主要原因是 OAuth、二维码轮询和多状态弹窗包含大量依赖外部授权状态的条件分支。

## 3. 测试执行方式

在 `frontend` 目录执行：

```bash
npx vitest run --coverage
```

覆盖率 HTML 报告生成于：

```text
frontend/coverage/index.html
```

## 4. Mock 与隔离策略

测试不依赖真实网络、真实 OAuth 服务或生产数据库。主要 Mock 内容包括：

- `framer-motion`；
- `lucide-react`；
- `echarts-for-react`、`echarts-wordcloud`；
- `react-router-dom`；
- `utils/api`；
- `utils/cache`、`utils/offlineStore`；
- `qrcode.react`、`cmdk`；
- `GlassCard`、`Toast`、`PosterModal`、`InsightDrawer`、`NutritionLabel` 等子组件；
- CSS 文件。

每个测试文件均使用独立 Mock，避免测试之间共享状态或相互污染。

## 5. 未覆盖重点区域

### Settings 页面

`Settings.jsx` 是当前覆盖率的主要瓶颈：

- 总语句数：361；
- 未覆盖语句：167；
- 当前覆盖率：约 53.74%。

主要未覆盖逻辑包括：

1. B 站和知乎二维码 OAuth 扫码轮询，约第 649—668 行；
2. 知乎 Cookie 凭据管理，约第 770—793 行；
3. 二维码模态框状态机，约第 847—910 行；
4. 部分隐私设置弹窗交互。

这些流程依赖真实的第三方授权状态、轮询时序和浏览器环境，单纯使用 jsdom 单元测试难以完整还原，建议使用 Playwright 或 Cypress 增加端到端测试。

## 6. 测试结论

本次前端测试共执行 864 个测试，全部通过，没有发现由测试暴露的功能回归问题。

语句覆盖率为 90.02%，行覆盖率为 91.12%，函数覆盖率为 92.70%，满足当前“语句覆盖率超过 90%”的要求。分支覆盖率为 77.81%，不影响语句覆盖率达标，但 OAuth、二维码轮询和隐私设置等关键分支仍需通过端到端测试进一步验证。

## 7. 后续建议

1. 使用 Playwright 覆盖真实登录后的 B 站/知乎 OAuth 流程；
2. 增加二维码过期、轮询成功、轮询失败和重复轮询测试；
3. 补充 Settings 页面的隐私设置确认、取消和异常提示分支；
4. 对前端覆盖率设置 CI 门禁：Statements 不低于 90%，Lines 不低于 90%；
5. 分支覆盖率可作为后续优化指标，逐步提升至 85% 以上。
