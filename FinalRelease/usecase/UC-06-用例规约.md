# 用例规约：UC-06 查看每日/周知识总结报告

> **所属模块**：📊 报告与分析  
> **项目**：InfoDigest（知食）— 全域碎片化信息捕获与数字饮食管理平台  
> **版本**：v1.0  
> **状态**：设计中

---

## 1. 用例概述

| 项目 | 内容 |
|------|------|
| **用例ID** | UC-06 |
| **用例名称** | 查看每日/周知识总结报告 |
| **用例简述** | 系统定时自动生成每日/每周的知识摄入总结报告，推送给用户查看。报告包含信息营养成分表（UC-07）和关注点流变分析（UC-08），用户可对报告进行分享海报生成等操作 |
| **参与者** | 用户 (User)、系统 (System) |
| **触发条件** | 定时调度器到达每日/每周的指定时间点 |
| **优先级** | 高 |
| **复杂度** | 高 |

---

## 2. 前置条件 (Preconditions)

| 编号 | 条件描述 |
|------|----------|
| P-01 | 用户已注册并登录 InfoDigest 系统 |
| P-02 | 用户已授权至少一个第三方信息源平台 |
| P-03 | 系统定时调度器正常运行 |

---

## 3. 后置条件 (Postconditions)

| 编号 | 条件描述 |
|------|----------|
| S-01 | 报告数据被持久化到数据库（UserReport 表） |
| S-02 | 用户收到站内通知，提醒查看报告 |
| S-03 | 用户可查看完整的报告内容（含营养成分表、流变分析、词云） |
| S-04 | （可选）用户可将报告生成分享海报 |

---

## 4. 包含关系 (Include)

| 被包含用例 | 说明 |
|-----------|------|
| UC-07 查看信息营养成分表 | 报告中嵌入 AI 对信息源的语义分类与营养度打分结果 |
| UC-08 查看关注点流变分析 | 报告中嵌入近期信息摄入话题的聚类分析与趋势变化 |

### 5.1 基本流步骤详解（RUP 格式）

| 步骤 | 参与者动作 | 系统响应 |
|:----:|------------|----------|
| 1 | | 定时调度器到达每日/每周指定时间点，触发报告生成任务 |
| 2 | | 查询用户当日所有已授权平台的信息源数据 |
| 3 | | 判断是否存在当日浏览数据 → 无数据则跳转备选流 A-01 |
| 4 | | 判断部分平台是否抓取失败 → 是则跳转备选流 A-04 |
| 5 | | 判断 AI 服务是否可能超时 → 是则跳转备选流 A-02 |
| 6 | | 调用 AI 对信息源执行语义分类与营养度打分（UC-07） |
| 7 | | AI 对信息源进行话题聚类，生成关注点流变数据（UC-08） |
| 8 | | 校验 AI 分类置信度是否 ≥ 85% → 低置信度则跳转备选流 A-03 |
| 9 | | 整合营养数据、流变数据、词云数据，渲染可视化日报 |
| 10 | | 推送站内通知告知用户"报告已生成" |
| 11 | 用户收到通知，进入报告页面查看 | |
| 12 | | 展示完整报告，包含营养成分表、流变分析、词云、AI 洞察金句 |
| 13 | 用户选择是否生成分享海报 | |
| 14 | （如选择生成）用户点击"生成海报" | |
| 15 | | 渲染海报图片，支持保存下载（UC-18） |
| 16 | | 用例结束 |

## 6. 备选流 (Alternative Flows)

### A-01：无浏览数据

| 项目 | 内容 |
|------|------|
| **触发点** | 基本流步骤 3：用户当日无任何信息源浏览记录 |
| **系统响应** | 生成空白报告，提示"暂无信息摄入" |
| **后置条件** | 空白报告保存到数据库，用户可查看但无数据内容 |
| **优先级** | 高 |

### A-02：AI 超时重试

| 项目 | 内容 |
|------|------|
| **触发点** | 基本流步骤 5：AI 服务可能超时（服务不可用/响应过慢） |
| **系统响应** | 1. 展示重试按钮，提示"AI 分析超时，是否重试？" |
| | 2. 用户点击"重试" → 返回基本流步骤 5，重新判断 AI 状态 |
| | 3. 用户点击"取消" → 本次报告生成任务作废，直接结束 |
| **后置条件** | 重试成功 → 继续基本流；取消 → 不生成本次报告 |
| **优先级** | 高 |

### A-03：低置信度内容

| 项目 | 内容 |
|------|------|
| **触发点** | 基本流步骤 8：AI 对部分信息源的分类置信度低于 85% |
| **系统响应** | 1. 在报告中标记可疑条目，提示"该条目分类置信度较低，建议手动修正" |
| | 2. 正常生成报告，低置信度条目不影响报告整体生成 |
| | 3. 用户可在报告中查看并手动修正分类 |
| **后置条件** | 报告正常生成，包含低置信度标记 |
| **优先级** | 中 |

### A-04：部分平台抓取失败

| 项目 | 内容 |
|------|------|
| **触发点** | 基本流步骤 4：部分第三方平台抓取数据失败（网络原因/平台风控） |
| **系统响应** | 1. 标记失败平台，记录失败原因 |
| | 2. 继续使用已成功抓取的其他平台数据生成报告 |
| | 3. 在报告中标注"部分平台数据不可用" |
| **后置条件** | 报告基于部分数据生成，缺失平台在报告中标注 |
| **优先级** | 中 |

## 8. 业务规则 (Business Rules)

| 编号 | 规则描述 |
|------|----------|
| BR-01 | 报告类型分为 DAILY（日报）和 WEEKLY（周报），由定时调度器按周期触发 |
| BR-02 | AI 分类置信度阈值 ≥ 85%，低于此阈值的条目需标记为"低置信度" |
| BR-03 | AI 超时重试次数不限，但每次重试需重新判断 AI 服务状态 |
| BR-04 | 部分平台抓取失败不影响报告整体生成，缺失数据在报告中标注说明 |
| BR-05 | 报告包含 UC-07（营养成分表）和 UC-08（流变分析）作为嵌入内容 |
| BR-06 | 空白报告仅包含"暂无信息摄入"提示，不包含营养/流变分析数据 |

## 9. 非功能性需求

| 编号 | 需求描述 |
|------|----------|
| NFR-01 | AI 营养分类准确率 > 85% |
| NFR-02 | 报告生成任务应在 30 秒内完成（含 AI 调用时间） |
| NFR-03 | 报告渲染支持响应式布局，适配 PC 和移动端 |
| NFR-04 | 海报生成使用 html2canvas，在 3 秒内完成渲染 |
